# OP21 - Exact decimal sum vs float64 sums

Dataset: A (`sales_fact`). Input: dataset A (CSV chunks for Track L, Parquet for Track S). Registry name: `decimal_arithmetic`.

`exact_sum_cents` = int64 sum of cents; `exact_sum_decimal` = that value formatted as `<int>.<2-digit>` (e.g. `123456.07`). Floats: with `v = cents / 100.0` (IEEE division), `naive_sum` = left-to-right sum of v in row order; `kahan_sum` = Kahan-compensated sum of v in row order. Float results are compared with rtol 1e-9; engines that sum in parallel are allowed to differ within that tolerance.

## Result

Result rows (digested, exact): columns `exact_sum_cents`, `exact_sum_decimal` - exactly one row.

Float results (not digested, rtol 1e-9): `naive_sum`, `kahan_sum`.

Report `checksum` and `row_count` via the result digest (spec/checksum.md, "Result digests"); `floats` as a JSON object. NULL values are digested as NULL, not as 0.

## Oracle

DuckDB over the generated Parquet files:

```sql
SELECT sum((unit_price * 100)::BIGINT)::BIGINT,
                   (sum((unit_price * 100)::BIGINT) // 100)::VARCHAR || '.' || lpad((sum((unit_price * 100)::BIGINT) % 100)::VARCHAR, 2, '0'),
                   sum(((unit_price * 100)::BIGINT)::DOUBLE / 100.0), fsum(((unit_price * 100)::BIGINT)::DOUBLE / 100.0) FROM sales
```
